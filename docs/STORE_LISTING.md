## 一、应用名称与简介

**应用名称（30 字符以内）**

```
XVPN · 分流隧道客户端
```

**简短说明（80 字符以内）**

```
导入你自己的 WireGuard / OpenVPN / Hysteria2 配置即可使用，自动分流、无需填规则。
```

**完整说明**

```
XVPN 是一个配置客户端：把你自己的 WireGuard（.conf）、OpenVPN（.ovpn）或
Hysteria2（分享链接 / config.yaml）配置导入进来，剩下的交给它。

它不提供节点、不提供订阅、不需要注册账号。你需要自备配置。

■ 它替你做了什么

· 自动分流：命中内置规则集（geosite-cn / geoip-cn）的流量直连，其余走隧道。
  域名与 IP 双重判定，不需要你写任何规则。
· 自动 DNS：生成两套解析——规则集命中的域名用直连解析器，其余走隧道内解析，
  并交叉校验两组答案是否一致。
· 自动翻译配置：WireGuard / OpenVPN / Hysteria2 的字段全部自动映射到内核配置，
  非法或过时的参数会被纠正成内核认可的写法，不需要你查文档。
· 记住多份配置：切换即重连，不用每次重新导入。

■ 它会告诉你「为什么打不开」

「连上了但某个网站打不开」通常有三种完全不同的原因，处置方式相反，
但现象一模一样。XVPN 会区分它们：

· 判为直连却失败 → 规则可能没覆盖，程序会自己学会并改为走隧道
· 走了隧道却失败 → 问题在节点或服务器，改规则没有用
· 直连本身不通 → 问题在本地网络或 DNS，不要怪节点

启动自检会分别验证「直连」与「隧道」两条路，DNS 监测会分别给直连解析器
与隧道解析器计时，并交叉校验两边的解析结果是否一致。

■ 数据与隐私

· 不收集任何个人数据，没有账号、没有分析统计、没有广告 SDK、没有追踪
· 配置、凭据、记录只保存在你自己的设备上，不上传
· 分流记录只记录域名与判定结果，不记录任何请求内容
· 开源（GPL-3.0-or-later），以上全部可在源码中核对

■ VpnService 用途声明

本应用使用 Android VpnService 的唯一目的是提供核心 VPN 功能：建立一条
加密隧道，并按你自己的配置决定哪些流量走隧道。本应用不通过 VpnService
收集任何个人或敏感数据，也不为任何变现目的重定向或操纵其它应用的流量。
隧道只在你主动连接时启动，并由系统弹出授权对话框确认。

■ 权限说明

· INTERNET / ACCESS_NETWORK_STATE：建立隧道、判断网络可用性
· FOREGROUND_SERVICE / FOREGROUND_SERVICE_SPECIAL_USE：隧道需在后台运行
· POST_NOTIFICATIONS：显示常驻运行通知（前台服务的系统要求）

不申请定位、相机、麦克风、通讯录、存储等任何与功能无关的权限。

■ 使用须知

本应用是客户端工具，不提供任何节点或服务。请自行确保你使用的配置与服务
符合你所在司法辖区的法律法规。
```

> **政策要点**：Google Play 会直接审查「应用说明里有没有写明 VpnService 的
> 用途」。上面「VpnService 用途声明」那一节就是为此写的，**不要删**。
> 历史上这条是硬性驳回原因（"Use of VpnService is not documented in the
> app description"）。

## 二、VpnService 用途声明（声明表单用）

Play Console 在检测到 `BIND_VPN_SERVICE` 后会要求填写声明。以下为建议答案，
按表单实际字段调整措辞。

**Q：你的应用为何使用 VpnService？请说明核心功能。**

```
XVPN 的核心功能就是在设备上建立一条用户自定义的加密 VPN 隧道。

用户导入一份 WireGuard（.conf）、OpenVPN（.ovpn）或 Hysteria2（分享链接 /
config.yaml）配置，应用把它翻译成内核（sing-box）配置，通过 VpnService 建立
TUN 接口，使这台设备的流量经由用户自己的服务器转发。

VpnService 是本应用存在的唯一理由——没有它，应用没有任何功能。
它属于政策中「核心 VPN 功能」这一类别。
```

**Q：请说明如何使用 VpnService，以及数据如何被处理。**

```
1. 用户在应用内点击连接，应用先通过 VpnService.prepare() 请求用户授权
   （系统弹出授权对话框）；未获授权则不会建立隧道。
2. 授权后，VpnService 创建 TUN 接口并交给内核（sing-box，GPL-3.0 开源项目）
   持有。内核按用户在配置文件中声明的服务器地址建立加密隧道。
3. 全部流量在设备与用户自己的服务器之间加密传输。本应用不运营任何服务器，
   数据不经过开发者。

数据处理：
· 配置文件（含密钥与凭据）保存在应用私有目录，仅本机可读，不上传。
· 应用的诊断功能会读取内核在本机提供的连接列表（仅回环地址 127.0.0.1），
  用于显示分流记录与实时速率；这些数据不上传。
· 应用不收集、不存储、不传输任何用户流量内容。
```

**Q：是否通过 VpnService 收集个人或敏感数据？**

```
否。本应用不通过 VpnService 收集任何个人或敏感数据。

应用内没有账号体系、没有分析统计、没有广告或追踪 SDK，也没有自建后端
来接收数据。完整说明见隐私政策。
```

**Q：是否重定向或操纵其他应用的流量？**

```
否。本应用不重定向也不操纵其他应用的流量，不存在任何变现动机：
应用内没有广告、没有订阅节点销售，也不存在流量相关的商业合作关系。

流量走向完全由用户自己的配置文件决定（用户自己声明哪些网段经隧道、
哪些直连），开发者不参与、也无法干预这一决策。
```

**Q：数据是否在设备与隧道端点之间加密？**

```
是。加密由内核（sing-box）按用户配置实现：WireGuard 使用
ChaCha20-Poly1305；Hysteria2 走 QUIC / TLS 1.3，加密套件由 TLS 协商
（通常为 AES-128-GCM 或 ChaCha20-Poly1305）；OpenVPN 按用户配置协商的套件
（通常为 AES-GCM）。本应用自身不实现加密，只负责生成配置与分流决策。
```

## 三、权限声明

| 权限 | 声明理由（Play Console 需要逐项说明） |
| --- | --- |
| `INTERNET` | 建立 VPN 隧道并与用户配置中声明的服务器通信；另在你点击「检查更新」时下载规则库 |
| `ACCESS_NETWORK_STATE` | 判断网络是否可用，以便在网络恢复后重连 |
| `FOREGROUND_SERVICE` | VPN 隧道必须在后台持续运行，否则系统会终止连接 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14+ 要求前台服务声明类型；本应用为 VPN 隧道（`vpn_tunnel`） |
| `POST_NOTIFICATIONS` | 前台服务必须有通知；用于显示「XVPN 运行中」并让用户可随时断开 |

`BIND_VPN_SERVICE` 是声明在 `<service>` 上的**系统级权限**，应用不申请它——
只有系统能绑定该服务，应用自身无法启动它。
