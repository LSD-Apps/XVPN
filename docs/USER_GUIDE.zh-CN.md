## 开始之前：三件必须先想清楚的事

### 1. XVPN 是什么

它是一台设备上的**客户端**：读入你提供的配置文件，建立到**你自己的服务器**的加密隧道，并按内置规则决定哪些流量走隧道、哪些直连。

### 2. XVPN 不是什么

| 它不是 | 因此本指南也不会 |
| --- | --- |
| VPN / 代理运营商 | 不提供任何服务器、节点、订阅或账号 |
| 「一键找线路」的工具 | 不推荐、不罗列、不协助获取第三方接入服务 |
| 服务端安装程序 | 不教你如何购买主机，也不替代各协议官方的服务端文档 |

**你必须自备合法可用的服务器与客户端配置。** 本软件只负责「连上去」和「分流」。

### 3. 合法使用是你的责任

请确认：你对服务器有管理权或明确授权；用途符合你所在地以及服务器所在地的法律法规与服务条款。常见且通常无争议的用途包括：远程管理自己的机器、加密访问公司/实验室内网、使用机构正式发放的 VPN 配置等。

完整声明见 [`LEGAL.md`](LEGAL.md)。下文均建立在「配置与用途合法」这一前提上。

## 你需要准备什么

按清单打勾；缺一项后面都会卡住：

1. **一台你有权使用的服务器**（云主机、家里的 NAS/软路由、公司发放的接入端等），**或者**管理员已经发给你的**现成客户端配置**（若已有文件，可从「步骤 3 — 安装」开始）。
2. 若需自建：服务器上已按**该协议官方文档**安装并运行了下列之一的**服务端**：
   - [WireGuard](https://www.wireguard.com/quickstart/)
   - [OpenVPN](https://openvpn.net/community-resources/)
   - [Hysteria2](https://v2.hysteria.network/)
3. 一份对应的**客户端配置**（见下一节）。
4. 一台可安装 XVPN 的设备：Windows、Linux 或 Android。
5. 从 [GitHub Releases](https://github.com/LSD-Apps/XVPN/releases) 下载的安装包（或按仓库 README 从源码构建）。

> 服务端怎么装、防火墙怎么开、证书怎么签——请查阅上表**官方文档**或你所在机构的运维说明。  
> **本仓库只覆盖客户端侧。**

## 配置长什么样（脱敏示意）

下面用**文档保留地址**（`192.0.2.0/24`、`example.com`）说明形态。  
**请勿照抄进生产环境**；密钥与真实地址必须换成你自己的。

### WireGuard（常见为 `.conf`）

```ini
[Interface]
PrivateKey = <你的客户端私钥>
Address = 10.0.0.2/32
DNS = 192.0.2.53

[Peer]
PublicKey = <服务器公钥>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0, ::/0
```

### OpenVPN（常见为 `.ovpn`）

通常含 `client`、`remote`、以及内联的 `<ca>` / `<cert>` / `<key>` 等块。  
XVPN 按内容识别；扩展名建议 `.ovpn`。证书与密钥不要发到公开地方。

### Hysteria2（常见为 `.yaml` / `.yml`）

```yaml
server: vpn.example.com:443
auth: <口令>
tls:
  sni: vpn.example.com
```

也支持部分环境给出的分享链接，或 sing-box 出站 JSON。字段以你服务端实际导出为准。

**安全：** 配置含私钥/证书/口令。不要贴到公开 issue；求助时务必脱敏。

## 一条完整路径：自建服务端 → 客户端分流

每一步只做一件事。

### 步骤 1 — 在服务器上准备好隧道服务

在你的服务器上启用 WireGuard、OpenVPN 或 Hysteria2 的**服务端**（三选一即可）。

**完成标志：** 用该协议的官方客户端或命令行，从另一台机器已经能连上。  
若服务端本身连不通，换 XVPN 也不会变好。

### 步骤 2 — 导出（或生成）客户端配置

| 协议 | 你通常会得到 | XVPN 怎么认 |
| --- | --- | --- |
| WireGuard | `wg-quick` 风格 `.conf` | 按内容识别；建议 `.conf` |
| OpenVPN | 客户端 `.ovpn`（常含内联证书） | 按内容识别；建议 `.ovpn` |
| Hysteria2 | `.yaml` / `.yml`；或分享链接 / JSON | 均按内容识别 |

公司/学校 IT 发放的文件：一般**不必**自己装服务端，直接进入下一步。

### 步骤 3 — 安装 XVPN

1. 打开 [Releases](https://github.com/LSD-Apps/XVPN/releases/latest)。
2. 按系统下载对应包（Windows / Linux / Android）。
3. 解压到**用户目录**再启动，例如 Windows 的
   `%LOCALAPPDATA%\Programs\XVPN`、Linux 的 `~/.local/opt/xvpn`。
4. 启动。

无账号、无注册。

**为什么建议装在用户目录：** 应用是就地自动更新的。装在 `C:\Program Files`
这类受保护目录里，**每次**更新都要过一次管理员授权（更新界面会主动问你要，
你也可以把目录搬到用户目录，之后就不再需要）；Linux 下由包管理器安装的位置
**不会**自动更新——那种情况请用包管理器升级。

### 步骤 4 — 导入配置

| 平台 | 怎么导入 |
| --- | --- |
| Windows | 拖入主窗口 / 「选择配置文件」 / 粘贴全文 |
| Linux | 选择文件 / 粘贴 |
| Android | 文件管理器「打开方式」→ XVPN，或应用内选择 / 粘贴 |

成功后出现在「配置文件」列表。可保存多份；切换会按新配置重连。

**导入失败时先查：**

- 文件是否其实是订阅 URL、压缩包或说明文档（需要的是**单份客户端配置正文**）；
- OpenVPN 是否缺证书块；WireGuard 是否缺 `PrivateKey` / `Peer`；
- 文本是否被聊天软件改坏了换行或引号。

### 步骤 5 — 连接

在「连接」页点连接。首次：

| 平台 | 系统会要求 | 实际接管 |
| --- | --- | --- |
| Windows / Linux | 设置系统代理（无需管理员） | 认系统代理的程序（浏览器等） |
| Android | 授予 VPN 权限 | 系统 `VpnService`（TUN） |

连接页会显示状态、上下行速率、本次连接流量概况。

**干净退出：** 桌面端关窗口默认进托盘、不断开（会提示仍在后台运行）；要用托盘「退出 XVPN」才会还原系统代理并结束内核。

### 步骤 6 — 看懂「分流」（不必先懂 geosite）

默认一句话：

> **命中「国内站点 / 国内 IP」规则的流量直连；其余走你的隧道。**

| 现象 | 含义 |
| --- | --- |
| 国内常用网站仍很快、不占服务器流量 | 多半走了直连 |
| 需经你服务器才能访问的内网/特定目标 | 应走隧道 |
| DNS 也跟路由同一套判断 | 减少「解析错了 → 路由也错」 |

**分流模式**（在「分流规则」页）：

| 模式 | 行为 |
| --- | --- |
| 智能分流 | 按规则集 + 你的域名规则（默认） |
| 全局代理 | 忽略规则，尽量都走隧道（改完通常要**再连一次**才完全生效，以界面提示为准） |
| 全局直连 | 不走隧道（排障或临时停用时有用） |

通常不必手写规则。个别域名总判错时，到「分流规则」页手工指定，或让程序在反复失败后自动纠正。

### 步骤 7 — 确认它真的在工作

1. 状态为已连接，速率或「本次连接」流量在增加。  
2. 看连接页「连接状态 / 自检」：直连、隧道、DNS 结论。  
3. 试一个应**直连**的国内站点，再试一个应**走隧道**的目标（例如只在隧道内可达的内网服务）。  
4. 失败时先看归因：规则问题还是服务器问题，再改对应那一层。

## 界面地图：五个页面各管什么

| 页面 | 一句话 | 常见操作 |
| --- | --- | --- |
| **连接** | 连上、看状态与流量 | 连接/断开、看自检与失败归因 |
| **分流记录** | 最近连过谁、直连还是隧道 | 按关键字筛选、理解某条为何进隧道 |
| **配置文件** | 你的多份配置 | 导入、切换、删除 |
| **分流规则** | 规则集、模式、域名走向 | 分流模式、检查更新、手工指定、白名单、学到的规则 |
| **设置** | 主题、日志等偏好 | 不改路由逻辑的选项 |

桌面端多为侧栏；窄屏/Android 多为底部标签。结构一致，只是布局不同。

## 日常使用（理得清）

| 你想做的事 | 去哪里 |
| --- | --- |
| 换另一份配置 | 「配置文件」 |
| 看哪些连接走了隧道 / 直连 | 「分流记录」 |
| 强制某域名直连或走隧道 | 「分流规则」 |
| 改智能 / 全局代理 / 全局直连 | 「分流规则」→ 分流模式 |
| 更新内置规则集 | 「分流规则」→ 检查更新 |
| 主题、日志 | 「设置」 |

**桌面端范围：** 当前用系统代理接管——浏览器和多数图形程序有效；不认系统代理的游戏、部分命令行可能不受影响。Android 用系统 VPN，覆盖更完整。详见 [`PROTOCOLS.md`](PROTOCOLS.md)。

**Linux：** 系统代理支持 GNOME 系与 KDE；其它桌面会如实报错。托盘需要 StatusNotifierItem 宿主。凭据优先系统钥匙串；缺失时明文落盘，导入时会写明。

| 功能 | 依赖 | Debian/Ubuntu | Fedora / Arch |
| --- | --- | --- | --- |
| 系统代理（GNOME 系） | `gsettings` | `libglib2.0-bin` | `glib2` |
| 系统代理（KDE） | `kwriteconfig5/6`、`dbus-send` | `kde-cli-tools`、`dbus` | `kde-cli-tools`、`dbus` |
| 凭据加密 | `secret-tool` | `libsecret-tools` | `libsecret` |

## 连不上或个别站点异常

### 先分清是哪一类

| 你观察到的 | 更可能的原因 | 你该做什么 |
| --- | --- | --- |
| 直连与隧道都失败 | 本地网络 / DNS / 本机防火墙 | 先修本地，别先怪服务器 |
| 直连正常，隧道失败 | 服务器、端口、密钥、服务进程 | 回服务端官方文档与日志 |
| 多数正常，个别域名异常 | 规则覆盖或判错 | 看归因 +「分流规则」；可手工指定 |
| 导入都失败 | 文件不是客户端配置 | 对照上文「配置长什么样」 |
| 只有浏览器以外的软件不走隧道 | 桌面系统代理范围 | 属当前桌面能力边界，见上节 |

### 向项目提问时请带上

1. 现象：你做了什么、期望什么、实际怎样；  
2. 连接页状态卡片结论（自检 / DNS / 失败归因）；  
3. **脱敏后的**配置（删私钥、证书、真实地址、口令）；  
4. 系统与版本号（设置页可见）。

更细的自愈与探针设计见 [`RESILIENCE.md`](RESILIENCE.md)。

## 常见问题

**Q：我没有服务器，只有订阅链接，能用吗？**  
A：本项目不提供、不解析订阅市场，也不协助获取第三方服务。若你合法持有**单份** WireGuard / OpenVPN / Hysteria2 客户端配置，可以导入；只有订阅 URL、没有标准客户端配置正文，不是当前设计目标。

**Q：必须三个协议都装在服务器上吗？**  
A：不必。装一种并导出对应客户端配置即可。

**Q：会上传配置或浏览记录吗？**  
A：不会。无账号、无分析、无后台。见 [`PRIVACY.md`](../PRIVACY.md)。

**Q：能改成全部走隧道吗？**  
A：可以。「分流规则」→「全局代理」（改动生效时机以界面说明为准，通常需重连）。

**Q：服务端安装命令写在哪？**  
A：不在本仓库。请用 WireGuard / OpenVPN / Hysteria2 **官方文档**或单位内部手册。

**Q：为什么改了规则，网站还是旧行为？**  
A：多数域名改判会在连接保持时热更新（约十几秒内）；分流**模式**切换往往要再连一次。仍不对就看「分流记录」里该域名实际命中了哪条。

**Q：自动更新失败了，或者我不想让它自己替换，怎么办？**  
A：下载完成后的确认步骤里会显示**安装包路径**，并有「复制路径」与「打开所在文件夹」两个按钮——自动替换可能因为权限、杀毒软件或只读目录失败，而这时安装包已经下载并校验过，解压覆盖安装目录即可（也可以拷到另一台机器上用）。安装失败时这条路径同样会显示出来。

**Q：和 sing-box 官方是什么关系？**  
A：本项目独立，无隶属、无背书。内核来自上游开源项目，见 [`NOTICE.md`](../NOTICE.md)。
